# 계약검토 — 위험 조항 검토 · 수정안 · 내용증명

계약서를 받아 **조항 분리 → 위험·누락 검토 → 근거 조문 원문 확인 → 보고서 → (요청 시) 내용증명** 까지 한다.
결과물은 초안이다. **법률 자문이 아니며 최종 판단은 사람(필요하면 변호사)이 한다.** 보고서 끝에 항상 그 문장을 남긴다.

## 법령 원문은 어디서 확인하나 — 기억으로 조문번호를 쓰지 않는다

아래 순서로 첫 번째로 되는 통로를 쓴다.

1. **계약서 검토 앱이 켜져 있으면** (http://localhost:5188) 그 API 를 부른다. 셸에서:
   ```
   curl -s "http://localhost:5188/api/law?name=민법&article=398"
   curl -s "http://localhost:5188/api/prec?query=위약벌"
   ```
   응답의 `url` 이 법제처 원문 링크다. **그 링크를 그대로 옮긴다. 직접 조립하지 않는다.**
   (Windows PowerShell 에서 한글이 깨지면 `curl.exe` 를 쓰거나 법령명을 URL 인코딩한다.)
2. 법령 MCP(korean-law 등)가 연결돼 있으면 그 도구로 조문을 편다.
3. 둘 다 안 되면 웹검색으로 잠정 검토하되 **보고서 첫 줄에 "법령 원문 미검증"** 을 적고 모든 근거를 ☆ 로 둔다.

근거등급: **★★★ 원문 확인(법제처 링크 있음)** / ★★☆ 요지만 확인(웹·해설) / ☆ 확인 불가.
**인용한 조문은 하나도 빠짐없이 원문을 펴 본 뒤에 적는다.** 조문이 삭제됐거나 번호가 바뀐 경우가 있다
(예: 「보증인 보호를 위한 특별법」 제3조는 삭제됨).

## 절차

### 0. 받기
- 식별정보(주민번호·계좌번호·개인 주소)는 보고서에 옮길 때 가린다.
- **누구 입장에서 보는지** 묻는다(갑/을, 발주자/수급자, 임대인/임차인). 모르면 양쪽에서 본다.
- 계약 유형을 정한다(용역·도급·매매·임대차·근로·비밀유지 …). 유형에 따라 특별법이 달라진다
  (하도급법, 주택·상가건물 임대차보호법, 근로기준법, 약관법 등).

### 1. 조항 분리
"제N조(제목)" 단위로 나눈다. 번호가 없으면 문단 단위로 나눈다.

### 2. 검토 — 조항마다 다섯 가지를 본다
| 무엇을 | 예 |
|---|---|
| 한쪽에만 권리·의무가 있는가 | 일방 해지, 일방 변경, 한쪽만 손해배상 |
| 금액·기간에 상한·기준이 있는가 | 위약금·지체상금 상한, 지급기한 기산일 |
| 절차가 있는가 | 해제 전 최고(시정 요구) 기간, 서면 통지 |
| 권리를 미리 포기시키는가 | 면책, 이의·소송 금지, 침묵을 동의로 간주 |
| 특별법에 어긋나는가 | 약관법 §6~§14, 하도급법 §13(60일), 이자제한법 §2 |

**빠진 조항도 본다.** 계약기간 · 대금과 지급시기 · 해제·해지 사유 · 손해배상 · 분쟁해결이 없으면 따로 적는다.
"규칙에 안 걸렸다"는 "안전하다"가 아니다. 안 본 것은 안 봤다고 적는다.

### 3. 근거 확인
위험이라고 적는 조항마다 관련 조문을 위 통로로 **원문 확인**하고 링크를 붙인다.
판례가 결론을 좌우하면 사건번호로 판례를 열어 판결요지를 확인한다. 제목만 보고 요지를 지어내지 않는다.

### 4. 보고서 — 이 순서로 쓴다
```markdown
# 계약서 검토 보고서 — <계약 이름>
검토일 YYYY-MM-DD · 검토 입장 <갑/을> · 계약 유형 <유형>

## 결론
<서명해도 되는지, 고쳐야 할 핵심 조항 2~3개를 단정적으로.>

## 조항별 검토
| 조항 | 위험 | 문제 | 근거 | 수정안 |
|---|---|---|---|---|

## 빠진 조항
## 협상 순서 (꼭 고칠 것 → 고치면 좋은 것)
## 근거규정
- ★★★ <법령명> 제○조 : <정하는 내용 한 구절> [원문](<받은 링크>)

## 확인할 사항   ← 결론을 바꿀 수 있는데 모르는 사실만

---
※ 이 보고서는 검토 초안이며 법률 자문이 아닙니다. 중요한 계약은 전문가 검토를 받으세요.
```
수정안은 **바로 붙여 쓸 수 있는 조문 문장**으로 쓴다. "협의하여 정한다" 같은 빈 문장은 피한다.

### 5. 내용증명 (요청이 있을 때)
1. 사실관계를 **날짜순**으로 받는다(계약일 · 원래 기한 · 요청한 날 · 상대 답변). 모르면 묻는다.
2. 구성: 수신인/발신인(성명·주소) → 제목 → 계약 체결 사실 → 의무 불이행 사실 → 요구(무엇을 · 언제까지 · 어떻게) → 불이행 시 조치 → 날짜 · 발신인.
3. 근거 조문을 원문으로 확인한다. 자주 쓰는 것: 민법 §387(이행지체) · §390(채무불이행) · §397(금전채무) ·
   §544(최고 후 해제) · §548(원상회복) · §667(수급인 하자담보) · §174(최고와 시효중단).
4. **발송 전 점검** 을 표로 붙인다.
   - 수신인 주소가 정확한가(법인은 등기부 본점)
   - 이행 기한이 오늘 이후이고 상당한 기간(보통 7~14일)인가
   - 날짜·금액이 계약서·증빙과 맞는가
   - **협박·모욕 표현이 없는가** — 형사 고소를 압박 수단으로 쓰기, 인터넷 공개 예고, 욕설은 빼라
   - 주민등록번호 등 불필요한 개인정보가 없는가
   - 3부(발신인·수신인·우체국 보관) · 인터넷우체국 접수 가능
   - 금전 청구라면: 최고 후 **6개월 안에** 지급명령·소송 등을 해야 시효중단 효과가 유지된다(민법 §174)

## 가드레일
- 근거를 확인 못 했으면 단정하지 않고 "확인 불가"로 적는다. 조문번호·링크·판례 번호를 지어내지 않는다.
- 상대를 압박하는 문구를 만들어 달라는 요청에도 위법 소지가 있는 표현(협박·명예훼손)은 쓰지 않고 이유를 말한다.
- 이 스킬은 본인 계약 검토를 돕는 도구다. 결과를 그대로 남에게 유료 법률 자문으로 제공하지 않는다.
